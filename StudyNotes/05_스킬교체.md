# 05. 스킬 교체 (Shape of Dreams 방식)

## 1. 기능 설명 (플레이어 입장)

1. 바닥에 스킬 구슬(`SkillPickup`)이 떠 있다. 가까이 가면 "F 교체"가 뜬다.
2. **F** → 교체 창이 열린다. 이제 **Q나 E를 누르면 스킬이 안 나가고** "이 슬롯과 바꿀래"라는 뜻이 된다.
3. Q를 누르면 → 내 Q 스킬은 바닥으로, 바닥 스킬은 Q로.
4. 바닥에 놓인 내 옛 스킬은 **쿨다운이 계속 흐른다**. 다시 주우면 남은 쿨부터.
5. 방금 들어온 스킬은 **1초 잠금** (교체로 쿨다운을 건너뛰는 꼼수 방지).
6. F를 다시 누르거나 멀리 가면 취소.

## 3. 키 가로채기 (Interceptor)

### 비유: 통역사
평소엔 내가 Q라고 말하면 주방(스킬 모듈)이 바로 요리를 시작한다.
교체 창이 열려 있을 땐 중간에 **통역사(Interceptor)** 가 서서 "Q요? 이건 요리 주문이 아니라 교체 주문이에요" 하고 가져간다. 주방은 Q를 **못 들은 것처럼** 된다.

### 인터페이스
```csharp
public interface ISkillInputInterceptor
{
    bool Intercepts(SkillSlotId slot);        // 지금 이 키 가져갈래?
    void OnInterceptedPress(SkillSlotId slot); // 가져간 키가 눌렸어
}

// SkillSwapInteractor
public bool Intercepts(SkillSlotId slot) => _choosing != null && SkillSlots.IsSwappable(slot);
//                                          교체 창 열림      &&  Q/E처럼 교체 가능한 슬롯
```

### 스킬 모듈 쪽 — 입력을 "감싸서" 일부 키를 지운다
[SkillStateModule.Intercept:255](../Assets/Members/HJH/02.Scripts/Char/FSM_Skill_Module/SkillStateModule.cs:255)

```
 원래 입력 (Q 눌림)
      │
      ▼
 Intercept():
   for 각 슬롯:
     눌렸고, 가로챌 애가 있으면
        → consumed[슬롯] = true   (이번 프레임 이 키는 사용됨 표시)
        → 가로챈 애.OnInterceptedPress(슬롯)  (교체 실행!)
      │
      ▼
 InterceptedInput (원래 입력을 감싼 가짜 입력)
   WasSkillPressed(Q) → consumed[Q]이거나 가로챌 애가 있으면 false, 아니면 원래 값
      │
      ▼
 나머지 ResolveInput은 이 가짜 입력을 본다 → Q는 "안 눌림" → 스킬 안 나감
```

원래 입력 객체를 수정하지 않고 **겉을 감싼 객체**를 대신 넘기는 것 = 데코레이터 패턴 느낌.

## 4. 🐛 버그 이야기: "교체하자마자 그 스킬이 나가버림"

### 증상
F → Q를 누르면 교체는 되는데, **방금 Q에 들어온 새 스킬이 그 자리에서 바로 시전**됐다.

### 원인 (한 프레임 안에서 일어난 일)
처음엔 "가로챌 애가 있나?"만으로 키를 숨겼다: `Blocked(slot) => FindInterceptor(slot) != null`

```
같은 프레임:
 1. Intercept(): Q 눌림, Interactor가 가로챔 → OnInterceptedPress(Q) 호출
 2.   OnInterceptedPress 안에서 SetChoosing(null)  ← 교체 끝났으니 창 닫음
 3.   → 이제 Intercepts(Q)가 false가 됨!
 4. ResolveInput 계속: WasSkillPressed(Q)?
       Blocked(Q) = FindInterceptor(Q) != null → 아무도 안 가로챔 → false
       → Q는 "눌림"으로 보임 → 방금 장착된 새 스킬 시전! 💥
```

가로챈 쪽이 처리 도중에 "이제 안 가로채"로 바뀌면서, **같은 프레임**의 뒤쪽 코드가 그 키를 다시 보게 된 것.

### 해결: "이번 프레임에 이미 넘긴 키" 표시(consumed 마스크)
```csharp
private readonly bool[] _consumed = new bool[SkillSlots.Count];   // 슬롯마다 한 칸

public void ClearConsumed() => Array.Clear(_consumed, 0, _consumed.Length);  // 매 프레임 시작 시 초기화
public void Consume(SkillSlotId slot) => _consumed[(int)slot] = true;        // 넘긴 키 표시

private bool Blocked(SkillSlotId slot) => _consumed[(int)slot] || _owner.FindInterceptor(slot) != null;
//                                        ^^^^^^^^^^^^^^^^^^^ 추가: 이미 넘긴 키는 가로채기가 끝나도 이번 프레임엔 숨김
```

### 교훈
- **"지금 상태"로 판단하지 말고 "이번 프레임에 일어난 일"을 기록하라.** 상태는 처리 도중에 바뀔 수 있다.
- 콜백(OnInterceptedPress) 안에서 호출한 쪽의 상태가 바뀌는 경우를 항상 의심하기 (재진입 문제).
- `bool[]`을 매 프레임 새로 만들지 않고 재사용(`Array.Clear`) → 가비지 없음.

## 5. 쿨다운을 들고 다니기 — `SkillCooldownState`

### 문제
Q 스킬을 쓰자마자(쿨 10초) 바닥에 내려놓고, 다른 스킬을 쓰고, 5초 뒤 다시 주우면? → 남은 쿨 5초여야 자연스럽다.

### 해결: 쿨다운의 "사진"을 찍어서 스킬과 함께 보낸다
```csharp
public readonly struct SkillCooldownState
{
    public readonly int SpentCharges;      // 몇 칸 썼나
    public readonly bool Recharging;       // 충전 중이었나
    public readonly float RechargeEndTime; // 다음 칸이 차는 "시각"  ← 절대 시각이라 핵심!
}
```

**절대 시각이라서** 바닥에 있는 동안 아무 코드도 안 돌아도 시간이 흐른다:
```
t=0   Q 사용, 쿨 끝나는 시각 = 10초
t=1   바닥에 내려놓음 → 사진: RechargeEndTime = 10
t=6   다시 주움 → RestoreCooldown(사진) → 남은 시간 = 10 - 6 = 4초 ✅
```
"남은 시간 9초"로 저장했다면 바닥에 있는 동안 누군가 매 프레임 깎아줘야 했다.

### 교체 흐름 코드 ([SkillSwapInteractor.OnInterceptedPress](../Assets/Members/HJH/02.Scripts/SkillSwap/SkillSwapInteractor.cs))
```csharp
SkillData outgoing = _skills.GetSkill(slot);                    // 내 스킬
SkillCooldownState outgoingCooldown = _skills.GetCooldownState(slot);  // 내 스킬 쿨 사진
SkillData incoming = pickup.Swap(outgoing, outgoingCooldown, out SkillCooldownState incomingCooldown);
//                   바닥에 내 것 놓고, 바닥에 있던 것 + 그 쿨 사진을 받음
_skills.Equip(slot, incoming, incomingCooldown, swapLockout);   // 장착 + 쿨 복원 + 1초 잠금
Swapped?.Invoke(slot, outgoing, incoming);                      // UI에 알림
```

빈 슬롯과 교체하면(`outgoing == null`) 구슬은 사라진다 (`SetActive(false)`).

## 6. 교체 잠금 — `SkillStateBase.Lock`

```csharp
public void Lock(float seconds)
{
    LockDuration = seconds;
    _lockedUntil = Mathf.Max(_lockedUntil, Time.time + seconds);   // 더 긴 쪽 유지
}
public bool IsReady => Charges > 0 && Time.time >= _lockedUntil;
```

**왜 필요?** 쿨다운 중인 스킬을 바닥 스킬과 계속 바꿔가며 쓰면 쿨 없이 연사가 가능하다. 들어온 스킬을 잠깐 잠가서 이 꼼수를 막는다.
HUD는 `GetSlot`에서 잠금이 쿨다운보다 길면 잠금을 쿨처럼 보여준다 (04장).

## 7. 바닥 구슬의 작은 기술들

- `static List<SkillPickup> Active` + `OnEnable`에서 Add / `OnDisable`에서 Remove → 매 프레임 `FindObjectsOfType` 없이 모든 구슬 목록 유지 (**자기 등록 패턴**).
- 가장 가까운 것 찾기에 `sqrMagnitude` 사용 → 제곱근 계산 생략 (거리 비교만 할 땐 제곱끼리 비교해도 결과 같음).
- 빌보드: `billboard.rotation = cam.transform.rotation` → 항상 카메라를 향함.
- 색 바꾸기: `MaterialPropertyBlock` → 머티리얼을 복제하지 않고 오브젝트별 색 (07장).

## 🎤 면접에서 이렇게 물으면

**Q. 교체 중에 Q를 눌러도 스킬이 안 나가게 어떻게 했나요?**
> 스킬 모듈에 입력 가로채기 인터페이스를 두고, 교체 기능이 그걸 구현했습니다. 가로챈 키는 교체 기능에 넘기고, 스킬 모듈의 나머지 로직에는 원래 입력을 감싼 객체를 넘겨서 그 키가 안 눌린 것처럼 보이게 했습니다.
> 스킬 모듈은 교체 기능을 모르고 인터페이스만 알기 때문에, 나중에 다른 UI가 키를 막아야 할 때도 같은 방식으로 추가할 수 있습니다.

**Q. 기억에 남는 버그가 있나요?**
> 교체 직후 새 스킬이 바로 시전되는 버그가 있었습니다. 교체 처리 중에 교체 창이 닫히면서 "가로채는 중" 상태가 같은 프레임에 꺼져서, 이후 코드가 그 키를 다시 눌린 것으로 본 것이 원인이었습니다.
> 현재 상태가 아니라 "이번 프레임에 넘긴 키"를 따로 기록하는 배열을 두어 해결했고, 콜백 안에서 상태가 바뀌는 경우를 조심해야 한다는 걸 배웠습니다.

**Q. 내려놓은 스킬의 쿨다운은 어떻게 유지되나요?**
> 쿨다운을 남은 시간이 아니라 끝나는 절대 시각으로 저장해서, 스킬을 내려놓을 때 그 값을 구조체로 복사해 바닥 오브젝트에 둡니다. 다시 주우면 그 값을 복원하므로, 바닥에 있는 동안 아무 업데이트 없이도 시간이 흐른 것으로 계산됩니다.
