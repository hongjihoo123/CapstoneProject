# 08. 디버깅에서 배운 교훈

> 난이도 🟢 · 30분 · [← 목차](README.md)

각 버그를 **증상 → 원인 → 해결 → 교훈** 순서로. 면접의 "어려웠던 문제" 질문에 그대로 쓸 수 있다.

---

## 1. 스킬 교체하자마자 새 스킬이 나감 (같은 프레임 문제)
- **증상**: 교체 창에서 Q를 누르면 교체와 동시에 Q의 새 스킬이 시전됨.
- **원인**: 가로챈 쪽이 처리 중에 창을 닫아 "가로채는 중" 상태가 꺼짐 → 같은 프레임 뒤쪽 코드가 Q를 다시 "눌림"으로 봄.
- **해결**: 이번 프레임에 넘긴 키를 `bool[] _consumed`에 기록해서 프레임 끝까지 숨김.
- **교훈**: 콜백 안에서 상태가 바뀔 수 있다. "지금 상태"보다 "이번 프레임에 일어난 일"을 기록하라. → [05장 §4](05_스킬교체.md)

## 2. QuaternionToEuler: Input quaternion was not normalized
- **증상**: 콘솔에 경고가 계속 쌓임. 에디트 모드에서도. 스택에 내 코드가 없음.
- **배경**: 회전 쿼터니언은 길이가 1이어야 한다. Unity **인스펙터**가 회전을 각도로 표시할 때 검사하므로 스택에 내 코드가 안 나온다.
- **원인**: ① 씬 파일(YAML)을 손으로 쓰면서 카메라 회전을 소수 4자리로 적어 길이가 1.0065 ② 매 프레임 회전을 곱해서 누적(`Rotate`, `RotateTowards` 반복)하면 오차가 쌓임.
- **해결**: 씬 값 정규화, 회전은 각도(float)를 누적해서 매번 `Quaternion.Euler`로 새로 만듦, 곱셈 결과는 `Quaternion.Normalize`.
- **교훈**: 씬 파일을 손으로 고치지 마라. 스택이 없는 경고는 "누가 불렀나"가 아니라 "어떤 **데이터**가 이상한가"를 찾아라.

## 3. 이펙트가 한 번 재생 후 사라짐 (stopAction = Destroy)
- **증상**: 칼날 이펙트가 첫 번째만 보이고, 이후 MissingReferenceException 폭주.
- **원인**: 외부 에셋 파티클의 Stop Action이 Destroy → 재생 끝나면 스스로 삭제. 풀(재사용 창고)이 삭제된 걸 다시 꺼내 씀.
- **해결**: 풀에 넣을 때 모든 파티클의 `stopAction = None`으로 강제 + 망가진 인스턴스 감지 시 버림.
- **교훈**: 가져온 에셋의 설정을 믿지 마라. 재사용하는 객체는 "망가졌을 수 있다"를 가정하라.

## 4. 머지 후 에셋 참조가 전부 Missing (.meta GUID)
- **증상**: git 병합 후 씬에서 스킬·킷 참조가 다 끊김.
- **원인**: `.meta` 파일에 충돌 표시(`<<<<<<<`)가 그대로 커밋됨 → Unity가 meta를 못 읽고 **새 GUID** 발급 → GUID로 연결되던 참조가 끊김.
- **해결**: 원래 GUID로 meta 복원.
- **교훈**: Unity에서 **GUID = 에셋의 주민번호**. `.meta`는 반드시 에셋과 같이 커밋하고, 충돌은 사람이 직접 해결. 커밋 전에 `<<<<<<<` 검색.

## 5. 일반 클래스에 [SerializeField] → 영원히 null
- **증상**: 팀원 코드가 스킬 상태(일반 C# 클래스)에 `[SerializeField] EventChannelSO`를 붙였는데 인스펙터에 안 나오고 항상 null.
- **원인**: 코드에서 `new`로 만드는 객체는 Unity가 직렬화하지 않는다.
- **해결**: MonoBehaviour(`SkillElementBridge`)가 스킬 이벤트를 듣고 채널로 전달.
- **교훈**: `[SerializeField]`는 MonoBehaviour/ScriptableObject(또는 그 안의 `[Serializable]`)에서만. → [02장 §3](02_Unity기초.md)

## 6. 공중에서 마우스를 움직이면 R 착지점이 바뀜
- **원인**: 착지점을 강하 시작 시점에 계산.
- **해결**: 시전 순간(Execution 생성자)에 고정.
- **교훈**: "입력을 **언제** 읽는가"도 설계다. 조준 스킬은 시전 순간 확정이 플레이어 기대와 맞다.

## 7. 대시 마지막 타격이 도착점에서 안 터짐
- **원인**: 타격을 시간(0.6초)에 묶음 → 대시 속도가 바뀌면 어긋남.
- **해결**: "대시가 실제로 끝난 순간"(`!IsDashing`) + `End()`에서도 보장.
- **교훈**: 게임 이벤트는 시간보다 **상태 변화**에 묶어라.

## 8. 공부 노트가 통째로 사라짐 😇
- **증상**: 예전에 만든 `StudyNotes/` 노트 9개가 없어짐.
- **원인**: 정확히 무엇이 지웠는지는 모르지만, 핵심은 git에 커밋하지 않은 새 파일(untracked)이었다는 것. 정리·되돌리기 작업(`git clean`, 브랜치 정리, 폴더 삭제 등) 한 번에 흔적 없이 사라진다. git은 커밋하지 않은 파일을 지켜주지 않는다.
- **교훈**: 남기고 싶은 건 **커밋**. 코드든 문서든. `git status`에서 `??`(untracked)로 보이는 파일은 아직 안전하지 않다.

## 9. 코드가 동작하는데 팀원이 못 씀 (과하게 정리된 코드)
- **증상**: 콤보 연출 파일(`ComboFeedbackUI`, 411줄)이 잘 동작했지만 UI 담당 팀원이 이해하지 못해 쓸 수 없었다.
- **원인**: 번호 구역, 구분선, 툴팁 범벅, 범용 헬퍼 등 "모든 경우 대비" 정리가 오히려 읽기를 막음.
- **해결**: 실제로 쓰는 연출 4개만 남겨 116줄로 다시 씀.
- **교훈**: 버그가 없어도 **읽히지 않는 코드는 팀에서는 실패한 코드**. 읽는 사람 기준으로 쓰기. → [07장 §3](07_연출과_타격감.md)

## 10. UI를 지웠더니 게임 느낌도 사라질 뻔함
- **증상(잠재)**: 콤보 히트스톱·흔들림이 UI 스크립트(`ElementComboHud`) 안에 있었다.
- **문제**: UI를 교체·삭제하면 콤보 타격감이 같이 사라진다.
- **해결**: 타격감 설정과 호출을 로직(`ElementComboChain`, `[Header("Feel")]`)으로 옮김.
- **교훈**: 게임 느낌(로직)과 화면 표시(UI)를 섞지 마라. UI는 지워도 게임이 같아야 한다. → [07장 §3](07_연출과_타격감.md)

## 디버깅 체크리스트

| 상황 | 먼저 의심할 것 |
|---|---|
| 스택 트레이스에 내 코드가 없다 | 에디터가 읽는 **데이터**(씬/에셋 값) → 검사 도구 만들기 |
| 첫 번째는 되고 두 번째부터 안 된다 | **재사용(풀링)**, 자기 파괴 설정, 이벤트 중복 구독 |
| 머지 후 Missing | `.meta` GUID |
| 가끔만 틀린다, 프레임레이트 따라 다르다 | `if` 대신 `while` 따라잡기, 시간 대신 상태 |
| 같은 프레임에 두 일이 동시에 일어난다 | 콜백 안에서 상태가 바뀌는지 (재진입) |
| 특정 순간에만 위치가 틀린다 | 입력을 **언제** 읽는지 |
| 플레이 두 번째부터 이상하다 | static 값이 남아 있는지 (도메인 리로드) |

## 🎤 면접에서 이렇게 물으면

**Q. 가장 어려웠던 버그는?** → 1번(교체 직후 시전) 또는 2번(QuaternionToEuler)을 "증상 → 원인을 찾은 과정 → 해결 → 배운 점" 순서로 1분 안에.

> (2번 예시) 회전 정규화 경고가 계속 떴는데 스택에 제 코드가 없었습니다. 인스펙터가 회전을 표시할 때 내는 경고라서였고,
> 그래서 호출자 대신 씬의 모든 회전 값을 검사하는 도구를 만들어 찾았더니, 씬 파일을 손으로 고치면서 소수 넷째 자리까지만 적은 카메라 회전이 원인이었습니다.
> 값을 정규화하고, 매 프레임 회전을 곱해 누적하는 코드도 각도 누적 방식으로 바꿨습니다. 그 뒤로는 씬 파일을 직접 고치지 않습니다.
