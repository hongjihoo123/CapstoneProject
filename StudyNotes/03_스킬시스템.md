## 3. 레시피 카드와 주문서를 왜 나눴나 (가장 중요)

```csharp
// SkillData.cs:63
public virtual ISkillExecution Begin(ISkillContext context)
{
    Execute(context);   // 한 방에 끝나는 스킬은 Execute만 구현
    return null;        // 진행 상황을 기억할 필요 없으면 주문서 없음
}
```

여러 프레임에 걸치는 스킬(대시 공격 등)은 `Begin`을 오버라이드해서 `return new Execution(this, context);`

**왜?** 레시피 카드(ScriptableObject)는 모든 손님이 **같은 카드 한 장**을 본다.
카드에 "지금 3번째 고기 굽는 중"이라고 적으면 다른 주문도 그걸 보게 되고, 에디터에선 플레이를 멈춰도 그 메모가 남는다.
→ 진행 상황은 **주문마다 새 주문서(Execution)** 에.

```
SkillData (에셋, 1개)          Execution (시전마다 new)
 maxRange = 8                   _dashTicksDone = 2
 tickCount = 3                  _landed = false
 damagePerTick = 15             _direction = (0.7, 0, 0.7)
      ▲ 읽기만                         ▲ 읽고 쓰기
```

`Execution`은 SkillData **안에 숨긴 private 클래스**라서 카드의 private 수치(`_data.maxRange`)를 바로 읽을 수 있다.

## 6. 쿨다운 — "충전식" + "끝나는 시각 저장"

[SkillStateBase.cs](../Assets/Members/HJH/02.Scripts/Char/FSM_Skill_Module/SkillStateBase.cs)

### 비유: 휴대폰 충전 슬롯이 여러 개인 보조배터리
대시가 2충전이면 → 2번 연속으로 쓸 수 있고, 한 칸씩 쿨다운만큼 걸려서 다시 찬다.

```
_spentCharges     몇 칸 썼나              Charges = MaxCharges - _spentCharges
_recharging       지금 충전 중인가
_rechargeEndTime  다음 한 칸이 차는 "시각"   ← 남은 시간이 아니라 끝나는 시각!
_lockedUntil      교체 직후 잠금이 풀리는 시각 (05장)
```

### 왜 "남은 시간"이 아니라 "끝나는 시각"?
- 남은 시간 방식: 매 프레임 `remaining -= deltaTime` → Update가 꼭 돌아야 함.
- 끝나는 시각 방식: `endTime = 지금 + 3초` 저장만. 물어볼 때 `endTime - 지금` 계산.
  → Update 필요 없음, **스킬이 슬롯에 없어도(바닥에 떨어져 있어도) 시간이 계속 흐른다** → 스킬 교체에 그대로 쓸 수 있었다 (05장).

```csharp
private void Refresh()   // 값을 읽을 때마다 "시간 지났으면 회수"
{
    while (_recharging && Time.time >= _rechargeEndTime)   // while: 여러 칸이 한꺼번에 찼을 수도
    {
        _spentCharges--;
        if (_spentCharges > 0) _rechargeEndTime += EffectiveCooldown;   // 다음 칸 충전 이어서
        else _recharging = false;
    }
}
```

- 쿨다운은 스킬이 **끝난 뒤(Exit)** 부터 돈다.
- `IsReady => Charges > 0 && Time.time >= _lockedUntil` — 충전이 있고 잠금도 풀려야 시전 가능.

## 7. 스킬 모듈의 이벤트 4개

[SkillStateModule.cs:65](../Assets/Members/HJH/02.Scripts/Char/FSM_Skill_Module/SkillStateModule.cs:65)

| 이벤트 | 언제 | 누가 듣나 |
|---|---|---|
| `SkillUsed(info)` | 시전 성공 | 콤보 판정, HUD, 원소 브리지, 패시브 |
| `LoadoutChanged()` | 어떤 슬롯의 스킬이 바뀜 (교체, 캐릭터 변경) | HUD (아이콘 다시 그리기, 키맵 갱신) |
| `SkillDenied(slot)` | 못 쓰는데 키를 누름 (쿨, 충전 없음, 잠금) | HUD (아이콘 흔들기, "아직!" 표시) |
| `SkillReady(slot)` | 못 쓰다가 쓸 수 있게 됨 | HUD (아이콘 반짝) |

### 포인트 1: SkillReady는 "변화 감지(edge detection)"를 로직이 한다
```csharp
// SkillStateModule.cs:186 — 매 Tick
bool ready = 화구.IsReady;
if (지난번엔_못씀 && 지금은_씀) SkillReady?.Invoke(slot);
_wasReady[slot] = ready;
```
UI가 매 프레임 "준비됐나?"를 비교하면 UI마다 같은 코드를 중복으로 갖게 된다. 로직이 한 번 감지해서 **"지금 막 준비됐어"** 라는 사건으로 알려주면 UI는 반응만 하면 됨.
새로 장착한 스킬은 이전 기록이 없어서 장착 순간 잘못 반짝이지 않는다 (`_wasReady.Remove(slot)`).

### 포인트 2: LoadoutChanged는 킷 장착 때 한 번만
`EquipKit`은 슬롯 3개를 `Equip`하는데, 그때마다 이벤트가 나가면 UI가 3번 다시 그린다. `_equippingKit` 플래그로 묶어서 **마지막에 한 번만** 발행.

### Equip 두 가지

```csharp
Equip(slot, data);                              // 그냥 장착 (새 쿨다운)
Equip(slot, data, cooldownSnapshot, lockSeconds); // 교체용: 쿨다운 이어받기 + 잠금 (05장)
```

## 8. 실제 스킬 3개

### ① 대시 방향: WASD 우선 — [SkillAim.TryMoveDirection](../Assets/Members/HJH/02.Scripts/Char/FSM_Skill_Module/SkillAim.cs)
```csharp
direction = context.MoveInputDirection;     // WASD 누르고 있으면 그 방향
if (방향이 있음) { Normalize; return true; }
direction = context.AimDirection;           // 아니면 마우스 방향
return false;
```
"도망칠 때는 키보드 방향, 서 있을 때는 마우스 방향" — 대부분 액션 게임의 대시 느낌. `DashSkillData`, `BlinkSkillData`가 공유.
**공용 함수로 뺀 이유**: 같은 규칙을 두 스킬에 복붙하면 한쪽만 고쳐지는 사고가 난다.

### ② DashStrike (체인 캐릭터 무기 스킬) — 시간보다 "상태"에 묶기
[DashStrikeSkillData.cs](../Assets/Members/HJH/02.Scripts/Char/FSM_Skill_Module/Chain/DashStrikeSkillData.cs) — 대시 중 2번 + **도착 지점에서 반드시 1번** 타격.
- 이동 중 타격: `while`로 놓친 타격을 따라잡음 (프레임이 끊겨도 빠지지 않음).
- 마지막 타격: "0.6초 뒤"가 아니라 **"대시가 실제로 멈춘 순간"(`!IsDashing`)** → 대시 속도가 바뀌어도 항상 도착점.
- `End()`에서도 착지 처리 + `_landed` 플래그로 한 번만 → 취소돼도 마지막 타격 보장.

### ③ ChainPullSpin (체인 R) — 주문서 안의 작은 상태 머신
[ChainPullSpinSkillData.cs](../Assets/Members/HJH/02.Scripts/Char/FSM_Skill_Module/Chain/ChainPullSpinSkillData.cs) — 상승 → 커서 지점으로 강하 → 착지 → 회전 공격.
- `enum Phase { Rise, Dive, Drop, Landed }`
- **착지점은 시전 순간 고정** (생성자에서 계산). 처음엔 강하 시작 때 계산해서, 공중에서 마우스를 움직이면 착지점이 바뀌는 버그가 있었다.
- 벽에 막히면 Drop(그 자리 수직 낙하).

### 원거리 스킬의 흔들림 (Gunner)
`PiercingBeamSkillData`, `ShockCannonSkillData`는 세 가지를 섞어 쓴다:
- `PlayShake` (충전 중 점점 커지는 진동) — 히트스톱 없이 흔들림만
- `PlayCameraKick(-방향 × 세기)` — 쏜 **반대 방향**으로 카메라가 툭 밀렸다 돌아옴 = 반동
- `PlayHitFeel` — 맞았을 때만 히트스톱
자세한 구현은 07장.

## 9. 패시브 — "필요한 알림만 받는 구독자"

public abstract class PassiveRuntime : IPassive

    public virtual void OnDamageDealt(in DamageDealtInfo info) { }   // 때렸을 때

## 🎤 면접에서 이렇게 물으면

**Q. 스킬 시스템 구조를 설명해 주세요.**
> 스킬 수치는 ScriptableObject(SkillData)에, 시전 한 번의 진행 상태는 시전마다 생성하는 실행 객체에 둡니다.
> 슬롯마다 상태 객체가 있어서 상태 머신이 한 번에 하나만 실행하고, 쿨다운도 상태 객체가 관리합니다.
> 스킬은 플레이어를 직접 모르고 ISkillContext라는 인터페이스로만 대시·데미지·이펙트를 요청합니다. 플레이어 쪽 구현은 어댑터 하나에 모여 있어서 플레이어 코드가 바뀌어도 스킬들은 그대로입니다.
> 시전·장착 변경·시전 실패·쿨다운 완료는 이벤트로 알려서 UI와 콤보 시스템이 구독합니다.

**Q. 쿨다운을 어떻게 구현했나요?**
> 남은 시간을 매 프레임 깎지 않고 "다음 충전이 끝나는 시각"을 저장해서, 값을 읽을 때 현재 시각과 비교합니다.
> 그래서 Update가 필요 없고, 스킬을 바닥에 내려놓아도 절대 시각 기준이라 쿨다운이 계속 흐릅니다. 여러 충전을 가진 스킬도 같은 구조로 처리합니다.

**Q. 프레임레이트가 낮아지면 타격이 빠지지 않나요?**
> 정해진 간격의 타격은 if가 아니라 while로 "지나간 타격을 모두 처리"하게 했고, 마지막 타격은 시간이 아니라 대시가 끝났다는 상태 변화에 묶어서 항상 도착 지점에서 터지게 했습니다.
